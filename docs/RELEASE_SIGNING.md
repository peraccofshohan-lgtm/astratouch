# Release signing — personal-use debug identity

AstraTouch is a **personal-use application**. It is not distributed on Google Play
and it has no production release key. Everything published here is signed with a
stable *debug* signing identity.

This document explains exactly what that means, why it is still safe to update
across versions, and what it is **not**.

---

## TL;DR

| Question | Answer |
| --- | --- |
| Is there a production keystore? | **No.** None exists and none is needed. |
| Are there GitHub signing secrets? | **No.** The pipeline needs none. |
| Is the APK signed? | **Yes**, with a stable personal-use debug identity. |
| Can a new version install over an old one? | **Yes** — the certificate bytes never change. |
| Is this key a production trust anchor? | **No.** See [Limitations](#limitations). |
| Is a private key committed to the repo? | **Never.** Only the public certificate is. |

---

## Why a *stable* debug identity, and not the default one

Android refuses to install an update whose signing certificate does not match the
installed one. That makes "which key signed this?" a correctness property, not a
formality.

Android's normal debug keystore (`~/.android/debug.keystore`) is **regenerated by
each CI runner**. If the release pipeline used it, every published build would be
signed by a *different* identity, and installing v1.0.3 over v1.0.2 would fail with
`INSTALL_FAILED_UPDATE_INCOMPATIBLE` — "App not installed". The user would have to
uninstall first, losing all data.

So the identity has to be *stable*. Two design constraints made that harder than it
looks:

1. **A private key cannot be committed.** So the key is re-derived on demand.
2. **An ECDSA certificate is not byte-stable.** Re-signing the same key produces a
   different certificate *signature* each time, and Android compares the
   certificate bytes — not just the public key.

### The solution

```
                    seed (ASTRA_DEBUG_SEED, or a built-in constant)
                                    │
                                    ▼
              scripts/derive-debug-keystore.py  ──►  EC P-256 private key
                                    │                (deterministic)
                                    │
             signing/astratouch-debug-cert.pem  ◄──┘
             (committed PUBLIC certificate)
                                    │
                                    ▼
                    PKCS#12 keystore (temporary directory only)
```

The script derives the key deterministically from the seed, then **pairs it with the
committed certificate** (`--cert-in`) instead of minting a fresh one. The keystore
is written to a temporary directory, used for the build, and discarded with the
runner. Because the certificate is a fixed file, the signing identity is
byte-identical on every run.

The committed certificate is 688 bytes of public data. It contains no private key.
Anyone can read it; that is the point — it is a public identifier, like a
fingerprint.

## The signing identity

| Field | Value |
| --- | --- |
| Subject | `CN=AstraTouch Debug, O=AstraTouch Personal, C=BD` |
| Key algorithm | EC P-256 (`prime256v1`) |
| Certificate SHA-256 | see `.github/signing-identity.txt` |
| Validity | 2024-01-01 → 2053-12-24 |
| Keystore alias | `astratouchdebug` |
| Keystore / key password | `astratouchdebug` (documented, non-secret) |
| Keystore format | PKCS#12 |
| Signature schemes | v1 (JAR) and v2 |

The validity window starts in the past so that clocks skewed slightly behind
don't reject the certificate, and runs 30 years so that a personal-use app never
expires mid-life.

The fingerprint is enforced: the release workflow reads
`.github/signing-identity.txt` and **fails** if the built APK's signer digest
differs. That turns a silent key rotation — which would strand every existing
install — into a red build.

## Where the keystore lives

Nowhere persistent, by design.

```
ASTRA_DEBUG_SEED (optional GitHub secret)
        │
        ▼
derive-debug-keystore.py ──► $RUNNER_TEMP/signing/debug.p12   (ephemeral)
        │
        ▼
Gradle reads ASTRA_DEBUG_KEYSTORE_FILE / _PASSWORD / _KEY_ALIAS / _KEY_PASSWORD
        │
        ▼
assembleDebugPersonal ──► signed APK ──► GitHub Release
        │
        ▼
runner is destroyed; the .p12 goes with it
```

Because the key is derivable, there is nothing long-lived to leak or to back up.
`.gitignore` rejects `*.jks`, `*.keystore`, `*.p12`, `*.pfx`, `*.b64`,
`key.properties`, and `*.pem` — except the single committed public certificate.

### About `ASTRA_DEBUG_SEED`

It is **optional**. If unset, a documented constant seed is used and the pipeline
still produces the identical identity. It exists so that the *derivation* can be
kept private: anyone holding the seed could re-derive the private key. For a
personal app the practical risk is low — the app is not distributed through a store
and the key protects nothing of value — but the option to move to your own seed is
there.

**If you set `ASTRA_DEBUG_SEED` later, the identity changes** and previously
installed versions can no longer be updated. Pick a seed once, if at all, and keep
it.

## Build types

| Build type | Signing | Minified | Debuggable | applicationId | Published? |
| --- | --- | --- | --- | --- | --- |
| `debug` | Android debug key (auto) | no | yes | `com.astratouch.app.debug` | no |
| **`debugPersonal`** | **stable debug identity** | **yes** | **no** | **`com.astratouch.app`** | **yes** |
| `release` | release key, if provided | yes | no | `com.astratouch.app` | no |

`debugPersonal` is the artifact users install. It inherits from `release` (R8,
resource shrinking, ProGuard rules) but is signed with the stable identity.

Note the application ids. The plain `debug` variant carries a `.debug` suffix, so it
installs *alongside* the real app and can never update it — useful for development,
wrong for distribution. `debugPersonal` deliberately keeps the real
`com.astratouch.app` so that **v1.0.3 replaces v1.0.2 in place**, keeping user data.

### Building it yourself

```bash
python3 -m venv .venv
.venv/bin/pip install cryptography
.venv/bin/python scripts/derive-debug-keystore.py \
  --out /tmp/debug.p12 \
  --cert-in signing/astratouch-debug-cert.pem

export ASTRA_DEBUG_KEYSTORE_FILE=/tmp/debug.p12
export ASTRA_DEBUG_KEYSTORE_PASSWORD=astratouchdebug
export ASTRA_DEBUG_KEY_ALIAS=astratouchdebug
export ASTRA_DEBUG_KEY_PASSWORD=astratouchdebug
export ASTRA_REQUIRE_SIGNING=1

./gradlew :app:assembleDebugPersonal
```

With `ASTRA_REQUIRE_SIGNING=1` the `verifyDebugSigning` task fails the build if no
keystore resolved, so a misconfigured environment produces an error instead of an
unsigned APK.

## The release pipeline

`.github/workflows/android-release.yml`, triggered by a `v*` tag:

1. Resolve the tag and reject anything that is not `vX.Y.Z`.
2. Check `gradle.properties` agrees (`versionName`, and
   `versionCode == major*10000 + minor*100 + patch`).
3. Derive the stable keystore and print its certificate fingerprint.
4. Assert the fingerprint matches `.github/signing-identity.txt`.
5. Run unit tests.
6. Run lint (release-blocking).
7. `assembleDebugPersonal`.
8. Reject a missing or suspiciously small APK (< 1 MB).
9. `apksigner verify` — must show a valid v2/v3 signature.
10. Assert the signer certificate equals the committed identity.
11. `aapt2 dump badging` — assert package, versionName, versionCode, minSdk, targetSdk.
12. Produce the APK, `SHA256SUMS.txt`, and `release-metadata.json`.
13. Re-verify the checksum (`sha256sum -c`).
14. Upload workflow artifacts.
15. Refuse to overwrite an existing release.
16. Publish the GitHub Release.
17. Re-download the published asset and re-check its SHA-256.

Gate 17 is the one that matters most: it verifies the bytes a *user* will download,
not the bytes that happened to be on disk.

### Published evidence

Run [`44602580072`](https://github.com/peraccofshohan-lgtm/astratouch/actions/runs/44602580072)
on tag `v1.0.2` passed all seventeen gates and published
[release `v1.0.2`](https://github.com/peraccofshohan-lgtm/astratouch/releases/tag/v1.0.2):

| Size | 5,948,860 bytes |
| SHA-256 | `848b571643a08d07e8cb8cac0b8b702abf7abfab9975d649af51f968cb0a9ff8` |

The signer digest reported by the pipeline is the same value pinned in
`.github/signing-identity.txt`, so the published artifact and the committed identity
agree.

## Limitations

Stated plainly, because pretending otherwise would be dishonest:

- **This is a debug-signed artifact.** It is cryptographically valid and
  update-compatible, but it is not a store-quality trust anchor. It would not be
  accepted by Google Play, and it carries no identity validation.
- **The keystore password is public.** `astratouchdebug` is committed to this
  repository. Publication is what makes the derivation honest rather than
  security-through-obscurity; it does not weaken the signature, but it does mean
  the password protects nothing.
- **Anyone with the seed can produce a package signed with this identity.** Because
  the derivation is deterministic and documented, this identity proves *integrity
  relative to what was published here* — not *authorship*. If that matters to you,
  verify the SHA-256 of the release against the value in the release notes and the
  workflow log.
- **Sideloading requires trusting this app.** Android will warn about installing
  from an unknown source, and Play Protect may flag a debug-signed build.
- **`minSdk` is 29.** Installations on older devices are impossible, not merely
  discouraged.

What it *does* guarantee: the APK is signed, the signature is valid, the signer is
the same identity as every earlier release, and the published checksum matches the
published bytes.

## Rotating the identity

Don't, unless you must. Rotation strands every install.

If you genuinely have to:

```bash
rm signing/astratouch-debug-cert.pem
python3 scripts/derive-debug-keystore.py \
  --out /tmp/new.p12 --cert-out signing/astratouch-debug-cert.pem
# then update the fingerprint in .github/signing-identity.txt
```

Users must uninstall the old app first. Note this in the release notes.
