# AstraTouch v1.0.1

A correctness release. Everything here came from a line-by-line review of v1.0.0 —
including three features that were documented as working but did not work.

**Recommended for anyone who installed v1.0.0.**

## Fixed — things that were broken

| Issue | Impact |
| --- | --- |
| Screenshot/recording sharing threw an exception | The Share button never worked |
| "Delete all data" kept your recordings | A privacy promise was not kept |
| The bubble never came back after a reboot on Android 12+ | The app's core purpose failed on modern Android |
| The `BATTERY_SAVER_ON` macro condition was hard-coded `false` | Macros using it always skipped |
| `NESTED` and `MULTI_PAGE` radial layouts drew exactly like `FULL_CIRCLE` | Four of eight layouts were aliases |
| Gradle could emit an unsigned release APK and still report success | Release-integrity hazard |
| The signature gate reported a vague error for an unsigned APK | Now fails explicitly |
| `setup-signing.sh` needed a terminal | Could not run headless |

## Added — recordings you can actually manage

The Screenshot studio now has a **Recordings** section: play, share, delete, and see
each MP4's size. Previously, recordings were created and then invisible — they sat
in private storage until you uninstalled.

## Added — release provenance

`release-metadata.json` and the release notes now include the **signing
certificate's SHA-256**. Compare it across releases: a change means the signing key
changed, which should never happen silently.

## Verification

Built and published by GitHub Actions with these gates, all of which must pass:

- tag `v1.0.1` matches `versionName` and `versionCode` (10001)
- 86 JVM unit tests pass; `lintRelease` clean
- the APK is signed by the release key, **not** the Android debug key, with v2 and
  v3 schemes present
- `aapt2` reports `com.astratouch.app`, `1.0.1`, `10001`, minSdk 29, targetSdk 36
- the published asset's SHA-256 is re-downloaded and re-verified after upload

## Install

1. Download `AstraTouch-v1.0.1.apk`.
2. Verify: `sha256sum -c SHA256SUMS.txt`
3. Install over v1.0.0 (data is preserved — the database migration is unchanged and
   schema version stays at 2).

## Upgrading from v1.0.0

No action needed. Profiles, macros, notes, clipboard history and settings carry
over. If you had recorded screens and could not find them, they are now listed in
the Screenshot studio.

## Known limitations

Unchanged and documented in
[docs/KNOWN_LIMITATIONS.md](https://github.com/peraccofshohan-lgtm/astratouch/blob/main/docs/KNOWN_LIMITATIONS.md):

- AstraTouch cannot intercept gestures performed on other apps — Android offers no
  API for that, and the workaround (an invisible full-screen overlay) is rejected
  by design.
- Clipboard history is captured only while AstraTouch has focus (Android 10+ rule).
- Screenshots need Android 11+ through the accessibility API; Android 10 falls back
  to MediaProjection with per-session consent.
- OCR is not shipped and its switch is visibly disabled rather than faked.
